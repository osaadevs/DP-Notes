Proxy

A stand-in with the same interface as the real object. It decides if, when and how the real object is reached.
Structural
Understand

The idea

Sometimes the client shouldn't reach the real object straight away. It may be too heavy to load, the user may not be allowed, or it may be on another server.

A proxy has exactly the same interface, so the client can't tell the difference. The proxy does its check first (permission, cache, lazy load, log) and only then forwards the call to the real object. Like a security guard at a door: same building, but you go through the guard.

How a call goes through

  1. The client calls getPage(5) on the Subject (it's really the proxy).
  2. The proxy checks first: access, cache, validation, log.
  3. If allowed, it creates the real object if needed and forwards the call.
  4. The real object does the work and returns.
  5. The proxy can cache or log the result, then returns it.

Proxy: write

Virtual proxy for the LMS question. The protection proxy is on the answers page.
Structural
Write

W1 Name it and say why 2–5 marks

I would use the Proxy pattern (a virtual proxy), which is a structural pattern. It provides a surrogate or placeholder for another object to control access to it.

Reasons: (1) only the pages the user is reading are loaded, so the document opens fast and uses little memory and bandwidth; (2) the proxy has the same interface as the real document, so the reader code doesn't change; (3) loaded pages can be cached so going back is instant.

Mapping: Subject = Document «interface» · RealSubject = LargeDocument · Proxy = DocumentProxy · Client = LMSReader.

W2 Class diagram

both implement the Subject; the proxy points to the real subject
W3 · Java
// 1. SUBJECT
public interface Document {
    Page getPage(int n);
}
// 2. REAL SUBJECT: costly to create
public class LargeDocument
        implements Document {
    private final String path;
    private final long[] pageIndex;
    public LargeDocument(String path) {
        this.path = path;
        // opens the file, reads its page index
        pageIndex = Storage.readIndex(path);
    }
    public Page getPage(int n) {
        // reads ONLY page n from the file
        return Storage.readPage(path,
                                pageIndex[n]);
    }
}
// 4. CLIENT: can't tell it's a proxy
Document doc = new DocumentProxy("notes.pdf");
doc.getPage(1);  // opens file, reads page 1
doc.getPage(2);  // reads page 2 only
doc.getPage(1);  // from cache, no file read
// 3. PROXY: same interface, lazy, cache
public class DocumentProxy
        implements Document {
    private final String path;
    private LargeDocument real; // null
    private final Map cache =
        new HashMap<>();

    public DocumentProxy(String path) {
        this.path = path;  // nothing loaded
    }

    public Page getPage(int n) {
        Page p = cache.get(n);
        if (p == null) {
            if (real == null)   // first use
                real = new LargeDocument(path);
            p = real.getPage(n); // 1 page
            cache.put(n, p);
        }
        return p;
    }
}
// Page and Storage (STUB file access):
// page "Proxy: complete code"

The proxy delays the costly part (opening the file and reading its index) until the first page is asked for, then forwards each getPage(n) to the real document, which reads that one page. The whole document is never loaded. Lecture version of the same idea: ProxyImage (page "Proxy: lecture examples").

Rare books in a restricted archive 2025 Q3.1(c), 3.5, 5m

Protection Proxy. ArchiveAccessProxy and RestrictedArchive both implement BookArchive. The user only ever gets the proxy. Its getBook(id) first checks the user's role and permission (for example, a researcher with an approved request and a valid membership), logs the access, and only then forwards to the real archive. Otherwise it throws AccessDeniedException. Example: a student asking for an 1820 manuscript is refused; an approved researcher gets it, and the access is logged.

// all classes: "Proxy: complete code"
public RareBook getBook(String id) {
  if (!user.hasRole("RESEARCHER")
      || !user.isApproved(id))
    throw new
      AccessDeniedException("No permission");
  AuditLog.record(user, id);    // log it
  return archive.getBook(id);   // forward
}

Different authorization options 2023 Q4.5 · 2024 Q4.5

Put a protection proxy in front of each protected service (AdminServiceProxy, ReportServiceProxy). It checks the user's role or permissions before forwarding. The services themselves stay free of security code.

If authorization is a series of checks (login → role → permission → 2FA), add a Chain of Responsibility (tab 08).

Implementing logging 2023 Q3.4, 5m

Two valid answers. Say which one you mean:

  • Singleton for the logger itself: one shared logger writing to one file (tab 01).
  • Logging proxy: to add logging around existing services without changing them, a proxy logs before and after each call and forwards it.

W5 Challenges → fix

  • Extra layer, slower response → don't use a proxy for cheap, public objects.
  • Stale cache → set an expiry time, or clear the cache when data changes.
  • Two threads create the real object → synchronize the lazy-creation check.
  • Proxy becomes a bottleneck / single point of failure → keep it stateless and run several copies (HA).
  • Interface changes → proxy and real object must be updated together.

Proxy or not?

Hospital login, online examyes, protection
Image editor, high-res photosyes, virtual
CDN, Netflix streamingyes, cache + protection
Mobile banking appyes, remote
Calculator, static menuno, nothing to control or delay

Mistakes: giving the proxy a different interface (that's Adapter) · arrow from RealSubject to Proxy · client creating the RealSubject itself.

Slide quiz: true or false?

Proxy and RealSubject are both subtypes of SubjectTrue
Polymorphism comes from both implementing SubjectTrue
RealSubject holds a reference to the ProxyFalse, it's the other way

Don't mix it up

  • vs Decorator: both keep the interface. Proxy controls access (usually one layer, may create the real object itself). Decorator adds features and is stacked.
  • vs Adapter: Adapter changes the interface; Proxy keeps it.

Virtual proxy: image viewer the image is loaded only when displayed

public interface Image {           // Subject
  void display(); }

public class RealImage implements Image {
  private final String fileName;
  private byte[] data;
  public RealImage(String fileName) {
    this.fileName = fileName;
    loadFromDisk();          // expensive
  }
  private void loadFromDisk() {
    System.out.println("Loading " + fileName);
    data = new byte[1024];   // simulated file
  }
  public void display() {
    System.out.println("Displaying "
        + fileName); }
}
public class ProxyImage implements Image {
  private final String fileName;
  private RealImage realImage;     // null
  public ProxyImage(String fileName) {
    this.fileName = fileName; }    // no load
  public void display() {
    if (realImage == null)         // 1st call
      realImage = new RealImage(fileName);
    realImage.display();           // forward
  }
}
// client
Image image = new ProxyImage("cat.jpg");
// nothing loaded yet
image.display();  // Loading, Displaying
image.display();  // Displaying only

Lecture output: the second display() reuses the RealImage, so the file is read once.

Protection proxy: bank login and withdrawal checks before forwarding

public interface Account {         // Subject
  void withdraw(double amount); }

public class RealAccount implements Account {
  private final String accountId;
  private double balance;
  public RealAccount(String id, double bal) {
    accountId = id; balance = bal; }
  public void withdraw(double amount) {
    if (balance >= amount) {
      balance -= amount;
      System.out.println("New balance: "
          + balance);
    } else
      System.out.println("Insufficient");
  }
}
// client
Account account = new AccountProxy(
    new RealAccount("A1001", 10000),
    "bank123", 5000);
account.withdraw(1500);  // allowed
account.withdraw(4000);  // daily limit
public class AccountProxy
    implements Account {
  private final Account realAccount;
  private final String password;
  private final double dailyLimit;
  private double withdrawnToday = 0;
  private boolean active = true;
  public AccountProxy(Account real,
      String password, double dailyLimit) {
    this.realAccount = real;
    this.password = password;
    this.dailyLimit = dailyLimit; }

  public void withdraw(double amount) {
    if (!authenticate(password)) return;
    if (!active) { System.out.println(
        "Account inactive"); return; }
    if (withdrawnToday + amount
        > dailyLimit) {
      System.out.println("Daily limit");
      return; }
    withdrawnToday += amount;
    realAccount.withdraw(amount); //fwd
  }
  private boolean authenticate(String pwd) {
    if (!"bank123".equals(pwd)) {
      System.out.println("Invalid password");
      return false; }
    return true;
  }
}

Correction: the slide's authenticate() tests "bank123".equals(pwd) without the !, so it rejects the right password. The version above rejects only a wrong one. The stored password is a demo value; a real system checks a hashed password against the bank's user store.

Rare books in full 2025 Q3.5

public interface BookArchive {
  RareBook getBook(String id); }
public record RareBook(String id,
                       String title) { }
public record User(String name,
    String role, Set approved) {
  boolean hasRole(String r) {
    return role.equals(r); }
  boolean isApproved(String id) {
    return approved.contains(id); }
}
final class AuditLog {          // STUB
  static void record(User u, String id) {
    System.out.println(u.name() + " read "
        + id); } }
public class AccessDeniedException
    extends RuntimeException {
  public AccessDeniedException(String m) {
    super(m); } }
public class RestrictedArchive
    implements BookArchive {
  public RareBook getBook(String id) {
    // STUB: the real archive database
    return new RareBook(id, "Diary"); }
}
public class ArchiveAccessProxy
    implements BookArchive {
  private final RestrictedArchive archive =
      new RestrictedArchive();
  private final User user;
  public ArchiveAccessProxy(User u) {
    user = u; }
  public RareBook getBook(String id) {
    if (!user.hasRole("RESEARCHER")
        || !user.isApproved(id))
      throw new AccessDeniedException(id);
    AuditLog.record(user, id);    // log
    return archive.getBook(id);
  }
}

Other lecture cases type of proxy in brackets

Hospital (protection): PatientService.viewPatient(id); the proxy lets a doctor and an administrator through and refuses a receptionist. Mobile banking (remote): the app's getBalance() looks local, but the proxy sends the request over HTTPS to the bank server. API gateway (remote + protection): one entry in front of microservices that authenticates, rate-limits and routes. Warehouse routing (smart): the proxy sends an order only to a warehouse with stock. Netflix / Spotify / Google Drive: subscription checks, caching, and thumbnails before the full file.
