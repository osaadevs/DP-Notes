State

An object behaves differently depending on which state it is in. Each state gets its own class.
Behavioural
Understand

The idea

Press "mute" on a TV remote. If the TV is on, it mutes. If it's off, nothing happens. Same button, different result, because of the state.

Without the pattern, every method is a big if (state == ON) … else if (state == OFF) …, and it grows with every new state. With State, each state is a class that knows what to do for each action and which state comes next. The main object (the context) just says "current state, you handle this".

The parts

PartJobDocument workflow (2024 Q3)
ContextHolds the current state, passes every request to it, has setState()Document
State «interface»One method per event; every state must have them allDocumentState
Concrete statesThe behaviour for that state; they call context.setState(next) to move onDraftState, ModerationState, PublishedState, ArchivedState

Designing it in 5 steps

  1. Draw the state diagram (states and events).
  2. Make the state table: state + event → what happens + next state.
  3. State interface = one method per event.
  4. One class per state implementing it.
  5. The context delegates: state.submit(this).

Don't mix it up

  • vs Chain: State asks "how should I behave now?" and the object delegates to its current state. Chain asks "who handles this?" and the request moves along handlers.
  • vs Strategy: same structure, but the client picks a strategy and it doesn't change itself. States switch themselves.

W1 Name it and say why 2–5 marks

I would use the State pattern, which is a behavioural pattern. It allows an object to change its behaviour when its internal state changes; the object appears to change its class.

Reasons: (1) the document has a fixed set of states and the same action behaves differently in each (edit works in Draft but is refused in Published); (2) it removes the if/else on a status field from every method; (3) each state's rules and transitions live in one class, and a new state is just a new class (Open/Closed).

Mapping: context = Document · state interface = DocumentState · concrete states = Draft, Moderation, Published, Archived.

  void edit(Document d, String text);
  void submit(Document d);
  void approve(Document d);
  void reject(Document d);
  void archive(Document d);

  private DocumentState state =
      new DraftState();

    state.edit(this, t); }

  public void approve() { state.approve(this); }
  public void reject()  { state.reject(this); }
  public void archive() { state.archive(this); }

    System.out.println("Under review"); }
  public void submit(Document d) {
    System.out.println("Already submitted"); }

Quiz 1, the lecturer's own State question: why, state diagram, UML, context code, then an Adapter twist.

Q1 Why State is appropriate 4m

A parking session has a fixed set of well-defined states (Available, Reserved, Occupied, Payment Due, Closed), and the same action behaves differently in each: enter() is allowed when Reserved but refused when Closed, and pay() only works in Payment Due. Without the pattern every method needs a growing if/switch on the status. With State, each state's rules live in one class, transitions are explicit, invalid actions are refused cleanly, and a new state (e.g. Overstay) is just a new class.

Self-checkout kiosk states · 2025 Q1.1(a), 1.4, 5m

How to incorporate the states, with an example transition

State pattern. Kiosk is the context and holds a KioskState. IdleState, ScanningState, PaymentState and CompletedState implement scanItem(), checkout(), pay(), cancel() and printReceipt(), the five events on the diagram.

Example: in ScanningState, pressing Checkout adds up the decorated items' getCost(), adds tax with TaxCalculator.getInstance() (Singleton) and moves to PaymentState. In IdleState, pay() is refused: "scan items first". All five states in full: "State: kiosk in full".

public class ScanningState
        implements KioskState {
  public void scanItem(Kiosk k,
                       CheckoutItem i) {
    k.addItem(i); }        // stay here
  public void checkout(Kiosk k) {
    double sub = k.subtotal();
    k.setTotal(sub + TaxCalculator
        .getInstance().calculateTax(sub));
    k.setState(new PaymentState());
  }
  public void cancel(Kiosk k) {
    k.clearItems();
    k.setState(new IdleState()); }
  public void pay(Kiosk k, double a) {
    System.out.println("Checkout first"); }
  public void printReceipt(Kiosk k) {
    System.out.println("Pay first"); }
}

Use of interfaces in this design 2024 Q3.4, 5m

  • DocumentState is a contract: every state must implement every event, so nothing is forgotten.
  • The context calls state.submit(this) without knowing which state it has: polymorphism, programming to an interface.
  • New states plug in without changing Document (Open/Closed, Dependency Inversion).
  • States are interchangeable at runtime and easy to mock in tests.

W5 Challenges → fix

  • Many classes (one per state) → only use it when states are finite and behaviour really differs.
  • Transitions spread across classes → keep the state diagram and table as documentation; validate in setState().
  • A new event changes every state → abstract base state with default "invalid action" methods.
  • Many state objects → share stateless states as Singletons.
Mistakes that lose marks: the context still has if (state == …) · state diagram without a start dot or event labels · no setState() in the context · association instead of realisation from the states to the interface · transitions to states that aren't in the scenario.

public abstract class BaseDocState
    implements DocumentState {
  public void edit(Document d, String t) {
    no(); }
  public void submit(Document d)  { no(); }
  public void approve(Document d) { no(); }
  public void reject(Document d)  { no(); }
  public void archive(Document d) { no(); }

    System.out.println("Not allowed in "

}
public class DraftState extends BaseDocState {
  public void edit(Document d, String t) {
    d.setContent(t); }          // stay

    d.setState(new ModerationState()); }

public class PublishedState
    extends BaseDocState {
  public void archive(Document d) {
    d.setState(new ArchivedState()); }

Smart parking: all states Quiz 1 · events: reserve, cancel, enter, exit, pay

public interface ParkingState {
  void reserve(ParkingSession s);
  void cancel(ParkingSession s);
  void enter(ParkingSession s);
  void exit(ParkingSession s);
  void pay(ParkingSession s, double amt);
}
// default: every event refused
public abstract class BaseParkingState
    implements ParkingState {
  public void reserve(ParkingSession s) {
    no(); }
  public void cancel(ParkingSession s) {no();}
  public void enter(ParkingSession s) {no();}
  public void exit(ParkingSession s) {no();}
  public void pay(ParkingSession s,
                  double a) { no(); }
  protected void no() { System.out.println(
      "Not allowed in "
      + getClass().getSimpleName()); }
}
public class AvailableState
    extends BaseParkingState {
  public void reserve(ParkingSession s) {
    s.setState(new ReservedState()); }
  public void enter(ParkingSession s) {
    s.setState(new OccupiedState()); }
}                                   // walk-in
public class ReservedState
    extends BaseParkingState {
  public void enter(ParkingSession s) {
    s.setState(new OccupiedState()); }
  public void cancel(ParkingSession s) {
    s.setState(new AvailableState()); }
}
public class OccupiedState
    extends BaseParkingState {
  public void exit(ParkingSession s) {
    s.setFee(s.hoursParked() * 100);
    s.setState(new PaymentDueState()); }
}
public class PaymentDueState
    extends BaseParkingState {
  public void pay(ParkingSession s,
                  double amt) {
    if (amt >= s.getFee()
        && s.getProcessor().pay(amt))
      s.setState(new ClosedState());
    else System.out.println(
        "Payment failed, still due");
  }
}
// final state: nothing allowed
public class ClosedState
    extends BaseParkingState { }

public interface KioskState {
  void scanItem(Kiosk k, CheckoutItem i);
  void checkout(Kiosk k);
  void pay(Kiosk k, double amount);
  void cancel(Kiosk k);
  void printReceipt(Kiosk k);
}
public class Kiosk {                 // CONTEXT
  private KioskState state =
      new IdleState();
  private final List items =
      new ArrayList<>();
  private double total;
  public void setState(KioskState s) {
    state = s; }
  // events, delegated to the current state
  public void scan(CheckoutItem i) {
    state.scanItem(this, i); }
  public void checkout() {
    state.checkout(this); }
  public void pay(double a) {
    state.pay(this, a); }
  public void cancel() { state.cancel(this); }
  public void printReceipt() {
    state.printReceipt(this); }
  // helpers used by the states
  void addItem(CheckoutItem i) {
    items.add(i); }
  void clearItems() {
    items.clear(); total = 0; }
  double subtotal() {
    return items.stream()
        .mapToDouble(CheckoutItem::getCost)
        .sum(); }
  void setTotal(double t) { total = t; }
  double getTotal() { return total; }
}
public final class TaxCalculator { // SINGLETON
  private static final TaxCalculator INSTANCE
      = new TaxCalculator();
  private final double rate = 0.18; // assumed
  private TaxCalculator() { }
  public static TaxCalculator getInstance() {
    return INSTANCE; }
  public double calculateTax(double sub) {
    return sub * rate; }
}
public class IdleState implements KioskState {
  public void scanItem(Kiosk k,
                       CheckoutItem i) {
    k.addItem(i);
    k.setState(new ScanningState()); }
  public void checkout(Kiosk k) {
    say("Scan items first"); }
  public void pay(Kiosk k, double a) {
    say("Scan items first"); }
  public void cancel(Kiosk k) {
    say("Nothing to cancel"); }
  public void printReceipt(Kiosk k) {
    say("No sale"); }
  static void say(String m) {
    System.out.println(m); }
}
// ScanningState: page "State: kiosk and
// interfaces" (scanItem stays, checkout ->
// Payment, cancel -> Idle)
public class PaymentState
    implements KioskState {
  public void pay(Kiosk k, double amount) {
    if (amount >= k.getTotal())
      k.setState(new CompletedState());
    else IdleState.say("Payment failed, "
        + "try again");     // stay here
  }
  public void cancel(Kiosk k) {   // edit cart
    k.setState(new ScanningState()); }
  public void scanItem(Kiosk k,
      CheckoutItem i) {
    IdleState.say("Cancel to add items"); }
  public void checkout(Kiosk k) {
    IdleState.say("Already at payment"); }
  public void printReceipt(Kiosk k) {
    IdleState.say("Pay first"); }
}
public class CompletedState
    implements KioskState {
  public void printReceipt(Kiosk k) {
    System.out.println("Receipt: "
        + k.getTotal());
    k.clearItems();
    k.setState(new IdleState()); }
  public void scanItem(Kiosk k,
      CheckoutItem i) {
    IdleState.say("Take your receipt"); }
  public void checkout(Kiosk k) {
    IdleState.say("Sale complete"); }
  public void pay(Kiosk k, double a) {
    IdleState.say("Already paid"); }
  public void cancel(Kiosk k) {
    IdleState.say("Already paid"); }
}

TV remote states OFF / ON / MUTE · events pressOn, pressOff, pressMute

public interface State {
  void pressOnButton(TV tv);
  void pressOffButton(TV tv);
  void pressMuteButton(TV tv);
}
public class TV {            // CONTEXT
  private State currentState =
      new OffState();
  public void setState(State s) {
    currentState = s; }
  public void pressOnButton() {
    currentState.pressOnButton(this); }
  public void pressOffButton() {
    currentState.pressOffButton(this); }
  public void pressMuteButton() {
    currentState.pressMuteButton(this); }
}
public class OffState implements State {
  public void pressOnButton(TV tv) {
    System.out.println("TV on");
    tv.setState(new OnState()); }
  public void pressOffButton(TV tv) { }
  public void pressMuteButton(TV tv) { }
}             // off and mute do nothing
public class OnState implements State {
  public void pressOnButton(TV tv) {
    System.out.println("Already on"); }
  public void pressOffButton(TV tv) {
    tv.setState(new OffState()); }
  public void pressMuteButton(TV tv) {
    System.out.println("Muted");
    tv.setState(new MuteState()); }
}
public class MuteState implements State {
  public void pressOnButton(TV tv) {
    System.out.println("Sound back");
    tv.setState(new OnState()); }
  public void pressOffButton(TV tv) {
    tv.setState(new OffState()); }
  public void pressMuteButton(TV tv) {
    System.out.println("Already muted"); }
}
TV tv = new TV();        // OFF
tv.pressOnButton();      // ON
tv.pressMuteButton();    // MUTE
tv.pressOnButton();      // ON
tv.pressOffButton();     // OFF

State: vending machine code, OOP and SOLID

The lecture's vending machine with State classes, then what each part of the pattern does in OOP terms.
Behavioural
Examples · theory
public interface VendState {
  void insertDollar(VendingMachine m);
  void ejectMoney(VendingMachine m);
  void dispense(VendingMachine m);
}
public class VendingMachine {     // CONTEXT
  private final VendState idle =
      new IdleState();
  private final VendState hasOneDollar =
      new HasOneDollarState();
  private final VendState outOfStock =
      new OutOfStockState();
  private VendState currentState;
  private int count;
  public VendingMachine(int count) {
    this.count = Math.max(count, 0);
    currentState = count > 0 ? idle
                             : outOfStock; }
  public void insertDollar() {
    currentState.insertDollar(this); }
  public void ejectMoney() {
    currentState.ejectMoney(this); }
  public void dispense() {
    currentState.dispense(this); }
  void setState(VendState s) {
    currentState = s; }
  VendState getIdleState() { return idle; }
  VendState getHasOneDollarState() {
    return hasOneDollar; }
  VendState getOutOfStockState() {
    return outOfStock; }
  int getCount() { return count; }
  void doReturnMoney() {
    System.out.println("Money returned"); }
  void doReleaseProduct() {
    count--;
    System.out.println("Product out"); }
}
class IdleState implements VendState {
  public void insertDollar(VendingMachine m) {
    System.out.println("Dollar inserted");
    m.setState(m.getHasOneDollarState()); }
  public void ejectMoney(VendingMachine m) {
    System.out.println("No money"); }
  public void dispense(VendingMachine m) {
    System.out.println("Payment required"); }
}
class HasOneDollarState implements VendState {
  public void insertDollar(VendingMachine m) {
    System.out.println("Already have $1");
    m.doReturnMoney();
    m.setState(m.getIdleState()); }
  public void ejectMoney(VendingMachine m) {
    m.doReturnMoney();
    m.setState(m.getIdleState()); }
  public void dispense(VendingMachine m) {
    boolean last = m.getCount() == 1;
    m.doReleaseProduct();
    m.setState(last ? m.getOutOfStockState()
                    : m.getIdleState()); }
}
class OutOfStockState implements VendState {
  public void insertDollar(VendingMachine m) {
    m.doReturnMoney(); }     // stay
  public void ejectMoney(VendingMachine m) {
    System.out.println("No money"); }
  public void dispense(VendingMachine m) {
    System.out.println("Sold out"); }
}

State objects are created once and reused. These vending IdleState classes are separate from the kiosk's.

OOP and SOLID in the State code name the concept → class/member → effect

ConceptWhereEffect
Interface + polymorphismDocumentState; state.submit(this)The context calls one method and the current state's version runs: no if/else on status.
Composition / delegationprivate DocumentState state in DocumentBehaviour is supplied by a replaceable object, so it changes when setState() swaps it.
Encapsulationtransition rules inside each state classOnly allowed moves exist; e.g. ArchivedState has no way back.
Inheritance (optional)BaseParkingState refuses every event by defaultConcrete states override only the events they allow.
