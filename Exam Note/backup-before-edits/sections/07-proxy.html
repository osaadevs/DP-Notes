Proxy

A stand-in with the same interface as the real object. It decides if, when and how the real object is reached.
Structural
Understand

The idea

Sometimes the client shouldn't reach the real object straight away. It may be too heavy to load, the user may not be allowed, or it may be on another server.

A proxy has exactly the same interface, so the client can't tell the difference. The proxy does its check first (permission, cache, lazy load, log) and only then forwards the call to the real object. Like a security guard at a door: same building, but you go through the guard.

How a call goes through

  1. The client calls getPage(5) on the Subject (it's really the proxy).
  2. The proxy checks first: access, cache, validation, log.
  3. If allowed, it creates the real object if needed and forwards the call.
  4. The real object does the work and returns.
  5. The proxy can cache or log the result, then returns it.

Proxy: write

Virtual proxy for the LMS question. The protection proxy is on the answers page.
Structural
Write

W1 Name it and say why 2–5 marks

I would use the Proxy pattern (a virtual proxy), which is a structural pattern. It provides a surrogate or placeholder for another object to control access to it.

Reasons: (1) only the pages the user is reading are loaded, so the document opens fast and uses little memory and bandwidth; (2) the proxy has the same interface as the real document, so the reader code doesn't change; (3) loaded pages can be cached so going back is instant.

Mapping: Subject = Document «interface» · RealSubject = LargeDocument · Proxy = DocumentProxy · Client = LMSReader.

W2 Class diagram

both implement the Subject; the proxy points to the real subject
W3 · Java
// 1. SUBJECT
public interface Document {
    Page getPage(int n);
}

// 2. REAL SUBJECT: expensive to load
public class LargeDocument
        implements Document {
    private List<Page> pages;
    public LargeDocument(String path) {
        pages = Storage.loadAll(path); // slow
    }
    public Page getPage(int n) {
        return pages.get(n);
    }
}

// 4. CLIENT: can't tell it's a proxy
Document doc = new DocumentProxy("notes.pdf");
doc.getPage(1);  // loads page 1 only
doc.getPage(1);  // from cache
// 3. PROXY: same interface, lazy
public class DocumentProxy
        implements Document {
    private final String path;
    private final Map<Integer, Page> cache =
        new HashMap<>();

    public DocumentProxy(String path) {
        this.path = path;  // nothing loaded
    }

    public Page getPage(int n) {
        if (!cache.containsKey(n)) {
            // load just this one page
            Page p = Storage.loadPage(path, n);
            cache.put(n, p);
        }
        return cache.get(n);
    }
}

Rare books in a restricted archive 2025 Q3.1(c), 3.5, 5m

Protection Proxy. ArchiveAccessProxy and RestrictedArchive both implement BookArchive. The user only ever gets the proxy. Its getBook(id) first checks the user's role and permission (for example, a researcher with an approved request and a valid membership), logs the access, and only then forwards to the real archive. Otherwise it throws AccessDeniedException. Example: a student asking for an 1820 manuscript is refused; an approved researcher gets it, and the access is logged.

public RareBook getBook(String id) {
  if (!user.hasRole("RESEARCHER")
      || !user.isApproved(id))
    throw new
      AccessDeniedException("No permission");
  AuditLog.record(user, id);    // log it
  return archive.getBook(id);   // forward
}

Different authorization options 2023 Q4.5 · 2024 Q4.5

Put a protection proxy in front of each protected service (AdminServiceProxy, ReportServiceProxy). It checks the user's role or permissions before forwarding. The services themselves stay free of security code.

If authorization is a series of checks (login → role → permission → 2FA), add a Chain of Responsibility (tab 08).

Implementing logging 2023 Q3.4, 5m

Two valid answers. Say which one you mean:

  • Singleton for the logger itself: one shared logger writing to one file (tab 01).
  • Logging proxy: to add logging around existing services without changing them, a proxy logs before and after each call and forwards it.

W5 Challenges → fix

  • Extra layer, slower response → don't use a proxy for cheap, public objects.
  • Stale cache → set an expiry time, or clear the cache when data changes.
  • Two threads create the real object → synchronize the lazy-creation check.
  • Proxy becomes a bottleneck / single point of failure → keep it stateless and run several copies (HA).
  • Interface changes → proxy and real object must be updated together.

Proxy or not?

Hospital login, online examyes, protection
Image editor, high-res photosyes, virtual
CDN, Netflix streamingyes, cache + protection
Mobile banking appyes, remote
Calculator, static menuno, nothing to control or delay

Mistakes: giving the proxy a different interface (that's Adapter) · arrow from RealSubject to Proxy · client creating the RealSubject itself.

Don't mix it up

  • vs Decorator: both keep the interface. Proxy controls access (usually one layer, may create the real object itself). Decorator adds features and is stacked.
  • vs Adapter: Adapter changes the interface; Proxy keeps it.
