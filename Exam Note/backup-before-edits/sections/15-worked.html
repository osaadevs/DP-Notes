Worked answer: 2025 Q4

A full multi-pattern question, answered at exam length. This is the style to expect.
Worked
25 marks
The question: an e-commerce platform. Credit card, PayPal and cash-on-delivery payments follow a common workflow (validate → process → send receipt), but processing differs. Orders go through automated checks (inventory, fraud, delivery area) that must be maintainable and extendable. A single global OrderID generator must give every order a unique ID.

4.1 Which patterns fit? Give reasons. 8m, 2 marks each

CasePatternReason (one or two lines is enough)
(a) common payment steps, different processingTemplate MethodThe order of steps is fixed in a final handlePayment(); only processPayment() is written by each payment type, so the workflow is standard and nothing is duplicated.
(b) checks in sequence, easy to extendChain of ResponsibilityEach check is a handler linked to the next; a failure stops the order. A new check is one new class and one link, with no change to the others.
(c) one global OrderID generatorSingletonOnly one generator exists, so one counter is shared by every part of the system and IDs are never duplicated.
(d) creating payment objectsFactory MethodThe customer picks the method at runtime; PaymentFactory.create(method) returns the right processor, so the client has no new or if-else.

public void placeOrder(Order o) {
  Validator chain = new InventoryCheck();
  chain.linkWith(new FraudCheck())
       .linkWith(new DeliveryAreaCheck());
  if (!chain.validate(o)) return; // Chain
  o.setId(OrderIdGenerator.getInstance()
          .nextId());           // Singleton
  PaymentProcessor p = PaymentFactory
      .create(o.getMethod());   // Factory
  p.handlePayment(o);           // Template
}

Worked answer: 2025 Q1

The self-checkout kiosk: State + Decorator + Singleton in one scenario.
Worked
25 marks
The question: a supermarket self-checkout kiosk. Customers scan items, add optional extras (gift-wrap, eco-bag, express packing) and pay. The kiosk works in states: Idle, Scanning, Payment, Completed. Item prices change with add-ons without a subclass for every combination. One global tax calculator must be used by every checkout counter.

1.1 Which patterns, with reasons 6m, 2 each

(a) kiosk statesStateThe kiosk behaves differently in each state (pay is refused while Idle). Each state is a class that handles the actions and the next transition, so there is no if/else on a status field.
(b) optional add-ons, dynamic priceDecoratorEach add-on wraps the item and adds its own cost and description, so any combination is built at runtime without 2ⁿ subclasses.
(c) one tax calculatorSingletonOne instance shared by all counters means one rate and one rule set, so tax is consistent everywhere.

1.2 + 1.3 Interface and class 5m + 5m

public interface CheckoutItem {
  double getCost();
  String getDescription();
}
public class GroceryItem
        implements CheckoutItem {
  private String name;
  private double price;
  public GroceryItem(String n, double p) {
    name = n; price = p; }
  public double getCost() {
    return price; }
  public String getDescription() {
    return name; }
}

Add-on decorators (GiftWrap etc.): tab 06 answers.

1.4 Kiosk states, example transition 5m

Kiosk (context) holds a KioskState; IdleState, ScanningState, PaymentState, CompletedState implement scanItem(), checkout(), pay().

Example: in Scanning, pressing Checkout adds up the items, adds tax and calls kiosk.setState(new PaymentState()). State diagram and code: tab 09 answers.

1.5 Singleton in the pricing flow 4m

Scanned items are decorated with their add-ons, so item.getCost() is the final item price. In the Payment state the kiosk adds them up and calls TaxCalculator.getInstance().calculateTax(subtotal). Every counter gets the same instance, so a rate change applies everywhere at once.

What these two worked answers teach

  • Every sub-part names one pattern and one or two reasons tied to the scenario. Short is fine.
  • The code parts are small: an interface, one class, or one method. Use the names in the question.
  • The later parts ask how the patterns connect ("integrate the Singleton into the pricing flow"). Say which class calls which, in which state or step.
