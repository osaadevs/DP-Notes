Write assumptions
The paper asks for them. One or two lines at the top.

"Which design pattern would you use? Give reasons." the most common part

  1. Name it and its group. "I would use the Decorator pattern, which is a structural pattern."
  2. Say what it does in one line. Each pattern's W1 has this sentence ready.
  3. Map the scenario onto the pattern's parts. "Coffee is the component, Milk and Sugar are decorators." Most of the marks are here.
  4. Give 2 or 3 reasons tied to the scenario. Not general praise. Say what problem it removes here.
  5. Draw something if it's worth 4 marks or more. A small class diagram is enough.
  6. Add code only if they ask for it. Interface first, then the class, then 3 lines of client code.

Assumptions you can reuse

  • The system is written in Java (or a similar OO language).

  • Only the classes needed to show the pattern are drawn. Getters and setters are left out.
  • Third-party systems can't be changed by us.

Reading the question

When the trigger words aren't obvious, and when one question needs several patterns.

Tricky cases

Still unsure? Ask what the problem is about

Making objects?Creational. One object → Singleton. Many types → Factory.
Wrapping or connecting objects?Structural. Use the wrapper test →
Who does what, and in what order?Behavioural. Fixed steps → Template. Passed along → Chain. Changes with state → State.

The wrapper test

Four patterns wrap something. Ask what the wrapper does.

Adapterchanges the interface (a plug adapter)
Facadesimplifies many classes into one (a waiter)
Proxysame interface, controls access (a security guard)
Decoratorsame interface, adds features, stackable (toppings)

Pairs people mix up one line each, good for "compare" questions

State vs ChainState asks "how should I behave right now?" The object keeps one current state and hands work to it. Chain asks "who will handle this?" The request moves along a line of handlers.
Template vs StrategyTemplate Method fixes the steps in a parent class and lets subclasses fill some of them (inheritance). Strategy swaps the whole algorithm for another object at runtime (composition).
Factory vs SingletonFactory decides which type of object to create. Singleton decides how many (just one). They are often used together.
Factory vs FacadeFactory creates objects. Facade uses objects that already exist and gives them one simple front.
Proxy vs DecoratorBoth keep the same interface and wrap one object. Proxy controls access and is usually one layer. Decorator adds features and is stacked many times.
Adapter vs FacadeAdapter converts one interface into another that the client expects. Facade puts one new, simpler interface over many classes.
